Flujo documentado del proyecto

Esta guia te deja elegir entre una vista tecnica y una vista para usuario final, manteniendo el mismo flujo operativo del proyecto segun el nivel de detalle que necesites.

Selecciona el tipo de documentacion que quieres consultar sin salir del centro de ejecucion y monitoreo.

Volver al panel

1. Inicio del panel

Entrada

El punto de arranque recomendado es bash scripts/run_panel.sh. Ese wrapper valida python3 y delega la ejecucion a panel/server.py, que publica la UI local en 127.0.0.1:8765 por defecto.

La portada del centro de ejecucion y monitoreo concentra el resumen del host, el briefing de ciberseguridad, la cinta de mercado y el acceso a los dos paneles operativos.

2. Flujo de inventario

Panel 1

Desde Inventario y paquetes puedes lanzar scripts/collect_inventory.sh en modo completo o rapido. El modo rapido evita generar el archivo comprimido de configuraciones para acelerar la corrida.

Cada ejecucion crea un snapshot en output/<host>_<timestamp> con manifest.txt, warnings.log, los reportes bajo text/ y, cuando aplica, configs/configs.tar.gz.

3. Flujo de paquetes

Update

El mismo panel dispara scripts/update_packages.sh en modo check o apply, con soporte para --no-refresh, --yes y control explicito de fuentes confiables.

Antes de aplicar, el flujo revisa seguridad, firmas y origenes. La allowlist local vive en config/trusted-sources.txt. Si el modo apply continua, el resultado queda en update-reports/<host>_<timestamp> con report.json, summary.txt, source-trust.txt, security.txt y cambios detectados.

4. Flujo de monitoreo

Panel 2

La vista de servicios consulta estado, backend, puertos esperados y capacidades de ssh, samba, docker y firewall. En SSH, el estado de sftp se deriva de la configuracion del servicio.

Cuando el host lo permite, el panel habilita acciones start, stop y restart, confirmacion adicional para acciones sensibles y lectura de logs recientes por servicio.

5. Revision de reportes

Visor

El visor permite filtrar ejecuciones, abrir detalles, previsualizar archivos, descargar artefactos puntuales, comparar corridas del mismo tipo y exportar CSV o resumentes operativos.

Para auditoria y seguimiento, los archivos mas utiles suelen ser manifest.txt, summary.txt, report.json, security.txt, source-trust.txt y los TSV de cambios planeados o aplicados.

6. Validacion y cierre

Control

La validacion rapida del proyecto se apoya en bash tests/run_tests.sh, que cubre sintaxis, deteccion, una corrida rapida del inventario y el backend Python del panel.

Ademas, la API local expone endpoints como /api/status, /api/services, /api/reports, /api/jobs/inventory y /api/jobs/update para diagnostico local e integraciones ligeras sin dependencias externas.

Secuencia recomendada de uso

Recorrido
  1. Levanta el panel con bash scripts/run_panel.sh y confirma el resumen del host en la portada.
  2. Ejecuta un inventario rapido si buscas velocidad o uno completo si necesitas incluir configuraciones relevantes.
  3. Revisa el snapshot generado en output/ para validar manifest, warnings y colectores clave.
  4. Lanza un check de paquetes para revisar cambios planeados, advisories y confianza de repositorios.
  5. Si el trust es aceptable, confirma el modo apply y valida despues el contenido de update-reports/.
  6. Consulta el panel de servicios para confirmar el estado de SSH, Samba, Docker y firewall tras los cambios.
  7. Usa el visor para comparar ejecuciones, descargar evidencia y, al cierre, corre bash tests/run_tests.sh si hiciste cambios en el proyecto.

1. Que hace este sistema

Resumen

Este centro te ayuda a revisar el estado general del equipo, generar inventarios, comprobar actualizaciones de paquetes y vigilar servicios clave desde una sola interfaz local.

No necesitas recordar todos los comandos: el panel organiza las acciones principales y te muestra la salida de cada proceso.

2. Como empezar

Inicio

Abre el panel y revisa la portada. Ahí veras el resumen del host, noticias de seguridad y los accesos a Inventario y paquetes y Servicios.

Si solo quieres una revision general del equipo, normalmente el mejor primer paso es ejecutar un inventario rapido.

3. Inventario del equipo

Panel 1

Usa el boton de inventario para crear un snapshot del sistema. El modo rapido tarda menos; el modo completo guarda mas contexto y configuraciones.

Despues puedes abrir el reporte generado para ver hardware, software, servicios, seguridad, contenedores y otros datos relevantes del host.

4. Revision de paquetes

Update

Primero usa Solo reporte para revisar que cambios propone el sistema antes de instalar nada.

Si el resultado se ve correcto, puedes pasar a Aplicar cambios. El panel te pedira confirmacion antes de continuar.

5. Monitoreo de servicios

Panel 2

En la vista de servicios puedes revisar rapidamente si SSH, Samba, Docker y el firewall estan activos, detenidos o con alguna limitacion.

Tambien puedes consultar logs y, cuando el entorno lo permite, iniciar, detener o reiniciar servicios desde la misma interfaz.

6. Donde revisar resultados

Reportes

El visor de reportes te deja abrir resultados recientes, comparar ejecuciones y descargar archivos utiles para respaldo o seguimiento.

Si algo no sale como esperas, empieza por revisar el resumen del reporte, las advertencias y los archivos de detalle disponibles en el visor.

Recorrido recomendado para usuario final

Guia
  1. Abre la portada y confirma que el equipo se vea correctamente identificado.
  2. Ejecuta un inventario rapido para obtener una vista general del sistema.
  3. Revisa el reporte desde el visor para entender el estado actual del host.
  4. Haz una comprobacion de paquetes en modo reporte antes de aplicar cambios.
  5. Solo si el resultado es correcto, confirma la aplicacion de paquetes.
  6. Valida en el panel de servicios que los componentes importantes sigan operando.
  7. Guarda o compara reportes si necesitas evidencia o seguimiento posterior.

Preguntas frecuentes

FAQ

Que opcion conviene primero

Si solo quieres entender el estado general del equipo, empieza con un inventario rapido y revisa su reporte antes de tocar paquetes o servicios.

Cuando debo aplicar paquetes

Solo despues de revisar el modo reporte y confirmar que los cambios planeados y la confianza de las fuentes coinciden con lo que esperas.

Donde veo si algo fallo

Empieza por el visor del reporte, el resumen de ejecucion, las advertencias y los logs del panel de servicios si el problema afecta un daemon concreto.
